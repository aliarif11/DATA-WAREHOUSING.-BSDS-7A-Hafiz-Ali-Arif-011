I used pandas to build the April fact and dimension tables. Negative freight charges remain as three credit notes.

For the three head-office moves (CU-105, CU-120 and CU-116), I use Type 2 because a shipment must keep the province that was valid on its date. I also use Type 2 for sector changes when historical sector reporting matters. CU-132 could use Type 3 if management only needs to compare the current sector with its immediately previous one; that is limited history, so the lab build still versions all six changes using Type 2. CU-140’s acquired-company rename is Type 1 because the desired display name is the current name. `SignedUp` is Type 0 because it records an immutable event. The Type 2 dimension has 47 rows: 41 current and six expired.

Overwriting the three moved customers would shift 883,350 kg of March freight to different provinces while leaving March’s total unchanged. The net province movement is only 552,900 kg because CU-116 moved into Punjab while CU-105 and CU-120 moved freight out of Punjab. A province-by-month total could therefore look plausible while the customer-level historical attribution is wrong. The integrated model keeps March on its old customer keys, so Punjab remains 7,566,850 kg.
